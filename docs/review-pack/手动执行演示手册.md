# Page 五分钟现场演示手册

> 更新于 2026-08-06

## 先明确演示目标

主演示不是跑测试，也不是播放预设结果，而是把 Page 当作真正的本地 Coding Agent 使用：

1. 先运行一个有计算错误的小程序。
2. 用自然语言让 Page 分析并修复它。
3. 现场批准写文件和运行命令。
4. 直接运行修改后的程序，确认结果正确。
5. 查看 Page 留下的会话和审计记录。

主演示优先使用 `.env` 中配置的 DeepSeek，也可以使用本机 Ollama。FakeModel 只用来解释恢复机制，不能当作真实模型演示。

一句话介绍 Page：

> Page 是一个在终端中运行的本地 Coding Agent。它能在指定工作区里读代码、改文件、运行命令，并把每一步保存下来，方便审计和中断恢复。

## 一、演示前准备

### 1. 确认 Page 可以启动

在 PowerShell 中执行：

```powershell
cd D:\workspace\page
python --version
python -m page --help
```

检查下面几项：

- Python 是 3.10 或更高版本；
- 帮助中能看到 `deepseek`、`openai`、`anthropic`、`ollama`；
- 帮助中能看到 `--cwd`、`--approval`、`--resume`、`--max-steps`。

如果 Page 还没有安装：

```powershell
python -m pip install -e .
```

### 2. 确认模型可用

只检查 `.env` 是否存在，不要在投屏时显示它的内容：

```powershell
Test-Path .env
```

预期结果是 `True`。DeepSeek 会发起少量网络请求并产生调用费用，任何时候都不要把 API Key 打印到终端。

如果不想依赖外网，可以提前启动 Ollama。需要临时指定模型时，使用：

```text
--provider ollama --model qwen3.5:4b
```

### 3. 重置演示目录

演示材料里有一个故意写错折扣计算的小程序。每次演示前，把它复制到临时目录。这样 Page 不会改项目源码：

```powershell
New-Item -ItemType Directory -Force artifacts\usage-demo | Out-Null
Copy-Item docs\review-pack\usage-demo-seed\* artifacts\usage-demo -Recurse -Force
```

先运行错误程序：

```powershell
python artifacts\usage-demo\checkout.py
```

预期看到：

```text
订单总额: 190.00 元
```

再查看需求：

```powershell
Get-Content -Encoding UTF8 artifacts\usage-demo\README.md
```

正确结果应为 `180.00 元`。到这里，面试官已经看到了一个真实、可运行、结果确实错误的程序。

## 二、五分钟演示流程

### 第 0～1 分钟：说明问题

执行：

```powershell
python artifacts\usage-demo\checkout.py
Get-Content -Encoding UTF8 artifacts\usage-demo\README.md
```

可以这样说：

> 程序把“优惠 10%”写成了“直接减 10 元”，所以结果是 190 元。接下来我不手动改源码，而是把任务交给 Page。

### 第 1～3 分钟：让 Page 分析和修复

启动交互模式：

```powershell
page
```

如果找不到 `page` 命令：

```powershell
python -m page
```

看到 `page[模型名]>` 后，先输入：

```text
/status
```

确认工作区、模型和审批策略正确，然后输入：

```text
请检查 artifacts/usage-demo 里的订单程序，解释为什么运行结果不符合 README。先分析原因，不要修改文件。
```

Page 解释原因后，再输入：

```text
现在修复它。只修改 checkout.py，修好后运行程序确认结果。
```

这里故意分成两轮，是为了展示 Page 能记住上一轮的任务，不需要每次重新交代背景。

Page 读取文件时不需要批准；修改文件或运行命令时会出现类似提示：

```text
approve patch_file {...}? [y/N]
approve run_shell {...}? [y/N]
```

先确认路径只在 `artifacts/usage-demo` 内，再输入 `y`。如果它想改其他文件，输入 `n`，然后重新强调“只修改 checkout.py”。

现场可以这样解释：

> Page 不只是给建议。它会在 Agent Loop 中读取工作区、选择工具、等待用户批准高风险操作、执行修改，再根据执行结果继续判断。默认的 `ask` 策略把最终控制权留给用户。

真实模型每次选择的工具可能不同。它可能用 `patch_file`，也可能用 `write_file`；只要修改范围正确、最终结果正确，就属于正常情况。

### 第 3～4 分钟：独立检查结果

Page 返回最终答案后，在交互窗口依次输入：

```text
/memory
/session
/exit
```

退出后，不直接相信模型说“已经完成”，而是自己运行程序：

```powershell
python artifacts\usage-demo\checkout.py
```

正确输出应为：

```text
订单总额: 180.00 元
```

再查看修改后的代码：

```powershell
Get-Content -Encoding UTF8 artifacts\usage-demo\checkout.py
```

可以这样总结：

> 这是一次完整的实际使用：用户提出任务，Page 读取并修改代码，用户批准副作用，Page 运行程序验证，最后我又独立检查了业务结果。

### 第 4～5 分钟：展示审计记录

找到最新运行目录：

```powershell
$latestRun = Get-ChildItem .page\runs -Directory | Sort-Object LastWriteTime -Descending | Select-Object -First 1
$latestRun.FullName
Get-ChildItem $latestRun.FullName
```

查看运行摘要：

```powershell
$report = Get-Content -Raw -Encoding UTF8 (Join-Path $latestRun.FullName 'report.json') | ConvertFrom-Json
$report.task_state | Format-List status,stop_reason,tool_steps,final_answer
```

查看实际执行过的工具：

```powershell
Get-Content -Encoding UTF8 (Join-Path $latestRun.FullName 'trace.jsonl') |
  ForEach-Object { $_ | ConvertFrom-Json } |
  Where-Object { $_.event -eq 'tool_executed' } |
  Select-Object event,@{Name='tool';Expression={$_.name}},result |
  Format-Table -Wrap
```

最后这样收口：

> Page 每次运行都会保存任务状态、逐步 Trace 和汇总 Report。正常使用是一层；Checkpoint、Action Journal 和恢复对账是另一层，用来处理失败和中断。

## 三、顺手展示交互能力

主演示中只需要讲清 4 个命令：

- `/status`：查看当前模型、审批策略和工作区；
- `/memory`：查看任务摘要、近期文件和工作记忆；
- `/session`：查看当前 Session 保存位置；
- `page --resume latest`：退出后恢复最近一次会话。

恢复会话后，可以输入 `/memory` 或 `/session`，证明会话已经从磁盘加载。现场不需要故意杀进程。

一次性任务也可以这样运行：

```powershell
page "请检查 artifacts/usage-demo/checkout.py，并说明折扣计算是否正确"
```

这种 one-shot 模式适合脚本或一次性检查；现场主演示应使用交互模式。

## 四、没有网络怎么办

按下面顺序处理：

1. 本机有 Ollama：切到 `--provider ollama --model qwen3.5:4b`，继续完整演示。
2. 网络不可用，但有预先录屏：播放从发现错误到修复成功的完整录屏，同时现场展示源码和运行工件。
3. 只有预生成实验 JSON：把它当作恢复机制的证据，不能说成正在使用真实模型。

FakeModel 的输出是预设的，只能验证运行时状态和恢复流程，不能证明模型理解了新任务。

## 五、被追问恢复机制时怎么演示

只有面试官问到“中断后怎么恢复”，再展示已经保存的 DeepSeek 实验结果：

```powershell
python scripts\interview_demo.py --scenario recovery --model deepseek --output artifacts\interview-recovery-deepseek-final.json --show-latest
```

需要讲清 4 点：

- `blind_resume` 是对照组，不是正常使用方式；
- `guarded_resume` 会先核对 Action Journal、文件 Hash 和后置条件；
- DeepSeek 小样本中，blind 为 4/6，guarded 为 6/6；这个结果不能说成线上成功率；
- 文件写入可以用前后 Hash 对账，任意 Shell、数据库和第三方 API 副作用不能自动套用相同规则。

自动化测试只在面试官继续追问时说明。现场不用等待 50 秒的快速回归，更不要把 pytest 当成产品主演示。

## 六、现场问题怎么处理

### Page 只解释，不改文件

提示词里要明确写出：“请修复”“只修改 checkout.py”“修复后运行程序”。如果步骤不够，可以把 `--max-steps` 从 8 调到 12。

### Page 想改演示目录外的文件

审批时输入 `n`，然后重新强调文件范围。不要为了让演示继续而批准越界操作。

### 模型请求失败

不要现场打印 `.env` 或排查 API Key。先切 Ollama；仍不可用就播放录屏，并展示已经生成的 `.page/runs` 工件。明确说明失败的是外部模型请求。

### 程序仍然输出 190 元

检查两件事：

1. 是否在演示前重新复制了种子目录；
2. Page 的写操作是否在审批时被拒绝。

需要重置时重新执行：

```powershell
Copy-Item docs\review-pack\usage-demo-seed\* artifacts\usage-demo -Recurse -Force
```

然后重新启动 Page。

### 8 步内没有完成

把 `--max-steps 8` 调成 `--max-steps 12`。不要降低验收标准，也不要扩大允许修改的文件范围。

## 七、不能说错的话

- 主演示使用 `page` 交互模式；只有 PATH 未配置时才用 `python -m page`。
- 写文件和 Shell 使用 `approval=ask`，确认范围后再批准。
- `180.00 元` 是业务结果；测试和实验数据只是辅助证据。
- DeepSeek、OpenAI、Anthropic 和 Ollama 是模型后端；Page 负责 Agent Loop、工具、审批、记忆、审计和恢复。
- 不说“Page 能保证所有任务成功”。模型、网络和任务复杂度都会影响结果。
- 不说“已经支持分布式事务”。当前是 Windows 单机本地实现。

## 八、演示前最后检查

- [ ] `.env` 存在，或本机 Ollama 已启动。
- [ ] `python -m page --help` 正常。
- [ ] 已把 `usage-demo-seed` 复制到临时演示目录。
- [ ] 修复前输出是 `190.00 元`。
- [ ] 能解释为什么正确结果是 `180.00 元`。
- [ ] 只批准 `artifacts/usage-demo` 内的操作。
- [ ] 修复后输出是 `180.00 元`。
- [ ] 能找到最新的 `.page/runs/<run_id>` 并展示 Report 和 Trace。
- [ ] 会使用 `/status`、`/memory`、`/session` 和 `--resume latest`。
- [ ] 已准备 Ollama 或完整录屏作为网络故障备份。
- [ ] Recovery 实验只在可靠性追问时展示。

完成这些检查后，主演示要证明的结论很简单：**Page 不只是有测试，它确实能被用户当作本地 Coding Agent 使用。**
