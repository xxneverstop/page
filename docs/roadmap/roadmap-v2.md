## 项目定位与首轮目标

Page 是一个本地 Python Coding Agent Harness。它面向真实代码任务，研究如何把正确的信息交给模型、让模型根据工具反馈迭代修复，以及如何用实验验证这些设计的收益和边界。

| 核心方向 | 研究问题 | 要留下的证据 |
| --- | --- | --- |
| **Context & Skill Engineering** | 有限上下文里怎样保留重要约束、过滤旧代码，并按需注入任务知识？ | 发送给模型的请求、上下文取舍记录、Context 和 Skill 对照 |
| **Reliable Agent Runtime** | 模型如何根据工具和测试结果继续修复？中断后怎样沿用已有结果？ | 多轮改码 Trace、原生工具调用配对、独立进程恢复和文件状态证据 |
| **Agent Evaluation & Optimization** | 哪种 Harness 策略对任务质量、成本和恢复安全有实际影响？ | 固定任务、独立 Verifier、配对数据、失败复盘与复测 |

```text
任务 → Agent Loop → Context / Skill → Provider
           ↑                             │
           │                             ↓
           └──── 工具结果 / 测试反馈 ← Tool Executor
                                          │
                              Journal / Checkpoint → 恢复原任务

Evaluator → 固定任务与环境 → Page → 独立 Verifier
                                  └→ Trace / diff / 指标
```

已有 Agent Loop、模型适配和工具权限。ContextManager 已按字符预算裁剪、压缩部分历史，并按文件版本筛选读取结果。已有部分原生 Tool Calling、Action Journal、Checkpoint、文件恢复对照，以及已提交的详细 Trace 和 Python 查看器。现有原生路径会拒绝一轮里的多个工具调用，通用真实任务评测和 Skill loader 仍待实现。历史 FakeModel 和 DeepSeek 恢复结果保留原口径，首轮真实任务另做实验。[当前 ContextManager](../../page/core/context/manager.py) · [既有实验归档](../../benchmarks/results/recovery-demo-archive/DATA_PROVENANCE.md)

## S1 — Agent Loop、工具编排与正常链路（P0）

**问题。** 模型能否依据本轮的工具和测试结果推进任务，并在无进展或预算耗尽时停下？

- 优先复现并修正连续合法写入被判漂移、成功 Shell 后误停、重复读取返回旧内容及恢复拒绝被自动解除。任一故障若跨阶段实现，先交付解除正常改码阻塞的最小修复和回归。
- 用现有 Loop 跑通「读代码 → 修改 → 运行开发测试 → 根据失败继续修复」。工具反馈提供退出状态、错误原因和有界的相关输出。开发测试供模型迭代，最终完成情况由评测侧的独立 Verifier 判定。
- 在一个已支持的原生协议上把同轮多个工具调用按顺序执行，保留调用与结果对应关系。先验确定性协议与只读顺序，涉及副作用的多调用恢复在 S4 验通后再纳入正式实验。执行前校验整轮调用结构，逐次核对权限、参数与预算。中途失败按协议返回结果或明确停止，不能继续发送缺失结果的续接请求。
- 复用已有步数控制和重复调用检查，区分有实质进展的同参读取与无效循环。任务、模型、工具和验收超时及累计预算与 S5 共用规则。
- **验收。** 固定样本能从测试失败进入第二次修复并通过独立验收，原生结果按顺序准确配对。越界工具、预算耗尽和未知副作用按预期停止，已有单调用保持兼容。

## S2 — Context Engineering（P0，重点）

**问题。** 在有限预算下，怎样让模型看到当前有效的代码、约束和进度，并能证明这些信息进入实际请求？

1. **上下文投影。** 复用现有 ContextManager 和 Memory，用保存的任务、历史与工具记录构建模型实际输入。保护系统规则、当前需求、关键约束、未完成工作和必要的工具调用配对。压缩只作用于发送内容，恢复所需原始记录保有独立的持久化边界。
2. **预算与压缩。** 在选定模型上先做一套可解释的输入预算，包含工具定义、实际消息和 S3 的 Skill，预留输出空间。大段日志优先保留退出状态、关键错误和可定位的截断引用。较旧历史用一份可追踪的进展摘要压缩，保留近期原生调用与结果。记录保护、截断及压缩决定。若使用估算 Token，和 Provider 返回的实际用量分别记录。
3. **文件版本感知。** 读取内容和来源版本取自同一快照。只有能够核验原来源且文件版本一致时复用。为摘要记录可定位的文件/版本来源，修改、删除或版本不明时失效，重新获取依据。第一版只处理明确的文件依赖。
4. **Provider 续接。** 本地 Prompt 过滤、压缩或注入 Skill 后，核对实际 Provider 请求及它引用的先前状态。原生续接可能走工具结果或历史消息路径。状态可信时保留配对，需刷新时从可验证的本地记录重建合规请求，无法安全重建时给出明确停止原因。

**验收。** 选一个原生协议捕获实际请求。在有噪声或长日志的任务里，核对预算、必要约束和近期调用仍有效。模拟停机期间文件被修改，核对续接请求使用新读取结果，或明确停止。S4 联合验证真实进程重启。保留同一快照下现有策略与优化策略的对照入口，S5 比较效果。[当前续接实现](../../page/core/providers/clients.py)

## S3 — 最小 Skill Engineering（P0，重点）

**问题。** 在固定任务和预算下，任务相关的指导能否减少无效探索或提升验收通过表现？

- 先做一份可验证的本地 `SKILL.md`，例如 Bugfix 工作流程。第二份按任务覆盖需要增加。以名称、描述和路径定位资源，显式选中后才读取正文，未选中的内容不进入请求。自动选择留给后续有证据的需求。
- 固定来源、版本与内容 Hash，记录实际注入与裁剪情况。Skill 单列预算并计入 S2 总输入预算。路径和大小有界，工具权限和审批由 Harness 决定。首版只加载受控文本和需要的本地参考内容。
- **验收。** 同一配置可重复开启或关闭 Skill，实际请求与记录一致，来源和预算可追溯。准备适用及不适用的任务给 S5 做配对，保留可能变差的结果。

## S4 — 可靠执行与任务恢复（P0，精简）

**问题。** 工具已经改了文件，进程却在提交结果或推进对话时退出，Agent 怎样继续原任务？

- 复用 Action Journal 和 Checkpoint。给逻辑调用稳定身份，执行前保存原工具调用、最终参数和恢复证据，执行后保存结果。同参的新调用仍是新动作，重启沿用原任务和调用，实际重试才增加尝试次数。恢复继续累计预算和重试次数，达到上限时停止。
- 使用三种重放规则：安全重试、先对账、禁止自动重放。按历史与当前策略中适用的最保守要求检查工具权限、审批和文件前后状态。后置条件已成立时跳过重复修改，有证据仍在前置状态才可重试，其余停下复核。未知 Shell 副作用禁止自动重放，已确认成功的 Shell 允许继续。合法后续写入不要求保留旧动作的文件 Hash。
- 已提交的 Result 是动作完成证据，历史、Memory 或 Checkpoint 写失败时只补缺失记录。开始记录落盘失败就停在副作用之前，结果未确认写入时不报告成功。身份或记录不兼容时明确拒绝，普通循环、自动 Checkpoint 和重启均不能自行解除拒绝。
- 从持久化证据补齐模型历史及原工具结果。恢复后的下一次 Provider 请求须将结果交给原调用，保留 S2/S3 的文件版本、约束和 Skill 规则。续接不可用时从可核验记录重建，无法确认时停止。
- 首版限定单机、单 Agent、单工作区和进程退出。优先验证现有会话 JSON 的提交边界，S4 开始时定下一种权威存储。具体字段、状态转换和选型写入开发 Plan。如果文件方案难以满足本地提交规则，再考虑 SQLite。外部副作用仍按工具对账。

**验收。** 确定性故障矩阵覆盖执行前保存失败、写后未提交、结果已提交但观察或 Checkpoint 落后、未知 Shell、外部编辑和损坏状态。用独立进程覆盖关键窗口，并测试恢复中再次退出。核对文件、调用次数、剩余预算和实际 Provider 请求，证明结果只补一次、修改不会误做第二次。保留故障前后 Trace、Journal 和独立验收。

## S5 — Agent Evaluation & Optimization（P0，重点）

**问题。** 上下文、Skill 和恢复策略，分别怎样影响完成质量、成本与安全？

### 任务、预算和证据

- 冻结 6–10 个小型真实任务，覆盖 Bugfix、跨文件、测试修复及受约束重构。从固定快照复制工作区，记录来源与许可、依赖、允许工具、预算和评分条件。适用时检查缺陷版失败、参考修复通过。重构还要验证目标约束。旧 FakeModel 集继续验证 Harness 合同。
- 在现有 Evaluator 上移除 fixture 名称硬编码，明确 `repo_root`，支持多文件判定，再迁任务定义。参考修复放在 Agent 无权读取的位置，最终评分测试和配置由评测侧保护。受控自有任务限定工具和命令并保留 Shell 审批。陌生代码、不可信测试或开放 Shell 使用经验证的隔离，任务 Shell 与 Verifier 都接入。核验只读挂载、网络和凭据边界、镜像版本、时限及进程、磁盘、日志上限。
- 批次开始前固定模型、协议、采样配置、快照、策略和 Skill 版本、故障点、费用与停止规则。每个任务、模型请求、Shell 和 Verifier 都须有时限。每次实际请求及内部重试都计数并查额度，记录失败调用、累计 Token 与估算费用，未知用量单列。超限停止并记录清理结果。
- 用 `manifest.json` 固定条件，启动即登记 `runs.jsonl`，完成、失败、取消、超时和拒绝逐次保存。每次保留 Trace、结果、diff 与验收记录。中断后可凭原工件汇总，未结算运行单列，重跑使用新标识。可分享的正式归档只保留脱敏证据。
- 默认 Trace 记录能关联 Task/Run、Iteration、逻辑模型请求、工具调用、动作和恢复结果的必要字段，兼容现有 `event` 与 `created_at`。当前公共字段和关联规则见 [Page Trace Format](../../TRACE_FORMAT.md)，查看器通过 `page-inspection-v2` 统一复盘。详细 Prompt、请求正文与工具输出仅显式开启，限制体积并脱敏。状态恢复依据持久化记录。

### 首轮实验

| 实验 | 做法 | 观察什么 |
| --- | --- | --- |
| **E0 基础改码** | 固定配置跑全部 6–10 题，从无故障状态启动 | 独立验收通过、失败条件与成本 |
| **E1 上下文** | 选有上下文压力的任务，对比同一运行时的基础策略与一套优化策略 | 实际输入 Token、关键约束保留、重复探索和通过情况 |
| **E2 Skill** | 选适用及不适用的代表任务，对同一份 Skill 做显式开/关配对 | 是否改进通过情况、工具效率，额外消耗或退化 |
| **E3 恢复** | 选固定「任务 + 故障位置」组合，对比 Blind/Guarded，保留无故障参照 | 故障后完成率、错误重放、意外覆盖与人工介入 |
| **E4 外部基线（可选）** | 在兼容任务上与外部 Agent 对比 | 整体表现及差异边界 |

E1–E3 可复用同一批任务中事先选定的代表子集。先做小批配对，再按费用决定重复次数，样本数在实验 Plan 中确定。固定模型、快照、权限和预算，每组只变化被测策略。E3 写清 Blind 关闭哪些恢复检查，权限与隔离保持一致，故障未命中的运行单列。有必要区分专业指导与增加指令量时，E2 可另加等长通用指导。E4 披露运行方式差异，归因依据同一运行时的配对。

### 验收

- [ ] E0 每题均尝试，E1–E3 各有配对结果。计划、已启动、未启动、异常、拒绝和故障命中数量可对账。正确拒绝单独计安全结果，未完成仍计入任务完成率分母。
- [ ] 质量用独立验收和任务约束衡量，效率看实际或单列估算的输入/输出 Token、请求数、无效工具操作、耗时和费用，可靠性看故障后完成与危险重放。小样本披露原始分子、分母和限制。
- [ ] 按证据区分模型判断、工具、上下文丢失或过期、Skill 不适用、预算、环境和恢复故障，证据不足写 `unknown`。选有代表性的案例做一次「失败证据 → 最小修正 → 回归 → 同条件复测」，保留无收益和负收益。
- [ ] 在正式运行前用离线试验确认验收保护、预算和中断结算生效。能从一个样本找到任务、有效模型输入记录、动作、diff、独立验收与代价。

## S7 — 按需展示优化与后续扩展

S1–S6 已使用 Page Agent Execution Inspector 作为持续观测和调试入口。S7 只在真实使用中出现需求时增加运行目录、评测工件、更多筛选、长 Trace 性能和展示细节。终端方式继续由 [scripts/watch_trace.py](../../scripts/watch_trace.py) 提供快速跟随。

自动选择 Skill、更多 Provider 的串行多调用、并行工具和更复杂的压缩策略，等评测有明确需求再安排。首轮限定单 Agent 和本地执行，既有权限检查与外部隔离各自验收。通用任务调度、分布式恢复、MCP 平台、插件系统、向量数据库和第二套运行时不在交付范围内。文件对账的保证限定在已测场景，不外推到任意 Shell、外部 API 或断电。
