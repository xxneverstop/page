# Page Trace Web

用浏览器查看 Page 的本地运行记录。左栏切换运行，中间按时间查看步骤，右栏展开每步的输入、决策和结果。

在仓库根目录运行以下命令，然后打开 `http://127.0.0.1:8765`。Python 3.10 及以上即可运行。

```powershell
python viewer/server.py
```

另开一个终端运行 Page。需要看完整提示词、实际 HTTP 请求和响应时，启动后发一条新问题。

```powershell
python -m page --trace-detail
```

面板默认跟随新运行，也可以从左栏选中旧运行复盘。点击时间线里的事件查看证据，切到「运行报告」看最终回答、对账结果和运行统计。`Ctrl+C` 可结束本地查看服务。

默认读取仓库的 `.page/runs/`。查看已归档的评测工件时，用 `--runs-dir` 指向直接包含 `run_*` 的目录。如果端口被占用，可用 `--port` 改端口。

```powershell
python viewer/server.py --runs-dir 'D:\path\to\evaluation\runs' --port 8766
```

| Roadmap v2 工作 | 在面板里核对什么 |
| --- | --- |
| S1 · Agent Loop 与工具 | 模型判定、参数、审批、执行状态和结果。对照下一次 HTTP 请求里的工具反馈。 |
| S2 · 上下文 | 字符预算、分段长度、压缩和陈旧内容剔除。将本地拼接文本与发送给 Provider 的请求体分别核对。 |
| S3 · Skill | 使用「全部」和原始字段检查将来采集的 Skill 事件。当前展示取决于日志里已有的证据。 |
| S4 · 恢复 | 检查点、跳过或可重试动作、人工复核原因，以及报告里的动作日志。 |
| S5/S6 · 评测与交付 | 在各自的运行目录复盘任务。模型完成和独立验收是不同记录，用量也以实际采集的字段为准。 |

运行数据沿用 `.page/runs/<run_id>/trace.jsonl`、`task_state.json` 和 `report.json`。Trace 按追加的位置更新，旧运行仍能查看已记录的事件。详细正文只在开启采集的运行里可用。缺少结束事件的运行标为「未结束」。

查看器通过 `127.0.0.1` 提供只读访问。详细日志可能含问题和源码，分享时请按项目开发资料处理。
